# Supplemental Code: The Convention Gap

Reproducibility package for "The Convention Gap: Towards Measuring Implicit
Communication in Cooperative AI Evaluation".

## Quick Start

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt              # pinned, verified on Python 3.13
python -m pytest tests/ -v                    # Run all 168 unit tests
jupyter nbconvert --to notebook --execute notebooks/reproduce_paper_figures_v9.ipynb
```

To rebuild the processed CSV datasets from the raw game logs before running the
notebook, use:

```bash
python -m src.regenerate_datasets              # ~5 minutes; overwrites data/processed/
```

## Privacy and re-identification

The shipped CSVs replace every hanab.live username with a 16-hex hash
(SHA-256 with a private per-project salt). The 13 known bot-family accounts
are kept as raw names because they are already publicly labeled as bots.
This scheme prevents *casual* re-identification but does not prevent a
determined re-identification attempt: game_ids are preserved and the
original JSON can be refetched via the public hanab.live API. The private
salt and the username→hash mapping are kept out of the bundle (see
`data/private/` — gitignored) so an attacker without either would need
to independently correlate game contents to identify a specific player.

## Human-Human corpus definition (Appendix B of the paper)

The shipped `data/processed/human_play_records.csv` contains 26,229 play
records from 1,431 hanab.live games (pre-exclusion). Of the 1,500 fetched
hanab.live games, 25 are not replayable (21 use the bottom-deck-play option,
4 contain an unsupported action type) and are dropped before any filter,
giving the 1,475 replayable games from which every count below descends.
The paper's H-H corpus is defined by (i) a **completed-games filter** —
keeping only games that reached a terminal state (natural deck-exhaustion,
perfect, or three strikes) and dropping *truncated* games (abnormal-end
marker or log that stops mid-game; see `game_end_reason` in the replay
engine) — and (ii) a two-tier bot exclusion (Appendix B):

- **Tier 1 (game-level)**: Verified bot family accounts, matched by the
  patterns `will-bot\d+`, `jabot\d+`, `clanker\d+`, `Inybot\d*`,
  `rand-bot\d+`, `mac-bot.*` → drop every game in which such an account
  **made a play**. Because the filter operates on the play-record table,
  a verified bot that only clued or discarded is not detected: one game
  (1762152) is retained on this basis and contributes 6 human plays.
  Excluding it as well gives 424 games / 9,011 plays and moves the
  headline gap by 0.02 pp.
- **Tier 2 (account-level)**: 29 flagged accounts with positive bot evidence
  (co-plays ≥90% with a verified bot, byte-identical inter-game timing with
  another account, or a bot version signature in their notes) → drop only
  these accounts' plays; keep their (possibly-human) partners' plays. Account
  identifiers are kept as hashes in `src/corpus.py` so the bundle does not
  label real users as bots.

Applying the completed-games filter and the exclusion via
`src/corpus.py::load_hh_corpus()` yields the paper corpus:
**425 games / 9,017 plays / 155 players**. A robustness variant that applies
only Tier 1 (plus the completed-games filter) gives **598 games / 13,089 plays**
with a headline gap of +29.5 pp (main analysis uses two-tier: +28.2 pp).

## Privacy

hanab.live usernames in `human_play_records.csv` and `hint_records.csv` are
hashed to 16-hex identifiers (SHA-256 with a project salt), matching the scheme
used in `hai_game_participant_map.csv`. The 13 verified bot-family accounts are kept as raw names (already public and
identified as bots). The private salt and username→hash mapping (`data/private/`)
are not shipped in the supplementary bundle.

## Reproducing All Paper Figures and Tables

The notebook reproduces every figure and table in the manuscript from the
processed CSVs:

The notebook is organized top-to-bottom in the order the figures and
tables appear in the manuscript. Cell numbers can shift when the notebook
is re-executed; navigate by the markdown headers instead. Each manuscript
figure/table cell prints its own numbers and saves a PNG to
`output/figures/` where applicable. Note on Figure A6
(`game_scores_all_settings.png`): the error bars are ±1 standard deviation
across games, not confidence intervals.

The `individual_skill` and `pair_type` columns shipped in
`human_play_records.csv` are computed over the post-exclusion 425-game
corpus (the paper's Table A4 classification, regenerated 2026-09-07 by
`src/analysis.py::add_individual_skill_columns` after
`src/corpus.py::load_hh_corpus`); rows outside that corpus carry empty
values in these two columns. In the 11 corpus games where only one
player's play records survive the bot screen (10 Tier-2 partner removals
plus game 1762152), `pair_type` duplicates the remaining player's skill
for both seats. The legacy `skill_level` column is retained unchanged for
byte-compatibility and reflects the older pre-exclusion classification;
use `individual_skill`.

## Agent Naming Convention

The manuscript uses HanabiData names throughout:
- **Intentional** (= `InternalAgent` in HOAD/code, `internal` in agent CSVs)
- **Full** (Eger et al. 2017; no HOAD counterpart; distinct from HOAD's `flawed`)
- **Outer** (same in both)

The display mapping is in `src/analysis.py:AGENT_DISPLAY_NAMES`.
